# QUESTiX LAB 画像処理：実機での確認

## 1. 1台のRGB-DカメラのRGB画像を保存する
ここからの接続と実行は、教員・開発担当者と準備します。ROS 2はセンサーとプログラムをつなぐ仕組み、トピックはデータの送り先を区別する名前です。ドライバーはカメラの値をROS 2へ渡すプログラムです。ROS 2、sensor_msgs、cv_bridge、OpenCVのPython環境を使い、使用するROS 2環境をsourceしてから実行してください。
カメラドライバーを起動し、ros2 topic list -t と ros2 topic info /camera/image_raw でsensor_msgs/msg/Imageのトピック名を確認します。
例：python3 robo_lab_camera_capture.py --topic /camera/image_raw --count 10 --interval 2 --output images
このスクリプトは画像の購読とPNGの保存だけを行い、ロボットを動かしません。撮影中はロボットを止め、対象物や照明を変える方法でも実験できます。
ImageではなくCompressedImageだけのドライバーの場合は、ドライバー側でraw画像を有効にするかimage_transportで展開してください。名前だけを変更しても型は変わりません。

## 2. まず画像処理で試す
保存したPNGを教材の「画像を開く」で選びます。色、二値化、輪郭の処理で同じ画像を比較します。
しきい値を一つ変え、対象の見逃しと背景の誤検出を記録します。

### 2.1 撮り方と画素数を比べる
同じ目印を、照明・露出・ピント・距離を一つずつ変えて撮ります。「撮り方を変える」で明るさ分布を見て、白飛びやぶれで色・輪郭が失われていないか確認します。HTMLの倍率は再撮影条件の簡略比較で、失われた情報を復元する機能ではありません。

### 2.2 領域の中心を測る
赤い目印を2つ置いた画像を「まとまりを見つける」で開きます。RGB/HSV、オープニング/クロージング、面積の下限、ROIを変え、見逃しと余計な検出を記録します。外部画像の正解は自動で分からないので、人が囲み枠を確認します。
OpenCVでは色変換・inRange、morphologyEx、connectedComponentsWithStatsなどに対応する流れです。この教材はJavaScriptの簡易実装で、実機のコードと画素境界や連結の定義が異なる場合があります。

### 2.3 カメラの校正と取り付けを確認する
ROS 2のsensor_msgs/msg/CameraInfoで内部パラメーターと歪み係数、画像サイズを確認します。未校正なら既知の格子などを使って校正します。解像度・切り出し・レンズ設定を変えたら、パラメーターとの対応も見直します。
幅が既知の平面の目印を正面から写し、画像上の幅とカメラの焦点距離から奥行きを見積もり、メジャーやLiDARと比較します。斜め向きや画面端の歪みがある画像には単純な幅の式をそのまま使いません。機体座標に直すにはカメラの取り付け位置・向きも必要です。

### 2.4 画像から走行判断へつなぐ
床のラインを静止したロボットのカメラで写し、中央・左・右・途切れ・暗い床の画像を保存します。暗い領域の横位置の平均を計算し、画像の中央からのずれと「左へ/右へ/停止」の判断を記録します。
HTMLの「ラインをたどる」は連続した簡略シミュレーションです。実機の走行やカメラのストリームには接続しません。実機実装ではタイムスタンプ、画像更新の遅れ、カメラの左右、モーターの回転方向を確認し、画像が欠けたり、ラインを見失ったりしたときは指令をゼロにする処理を用意します。速度と曲がる強さは別々に変え、見つけ方と曲がり方のどちらが原因か切り分けます。

## 3. 教師あり学習で試す
教材の分類器は「荷箱」「ボール」の2種類、色・形の単純な特徴を使います。対象を中央に大きく写し、背景を単純にします。任意の物体を高精度に認識する汎用モデルではありません。
画像ごとに正解を登録します。学習に使わない実機画像は別に保存し、開いて判定を確認します。内蔵の10枚テストは教材画像での比較であり、実機画像の精度を示すものではありません。
連続撮影の隣り合った画像を学習用とテスト用に分けるだけでは、似た画像での成績になります。日、背景、距離など撮影場面を分けましょう。

## 4. ARマーカーで試す
教材の印刷用SVGにはArUco DICT_4X4_50のID 0〜3と白い余白を含めます。プリンターの縮小に注意し、距離を測る場合は黒枠の一辺を実測してください。
教材はIDの読み取りのみです。実機側ではOpenCVのcv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_4X4_50)とArucoDetectorで識別できます。
位置・姿勢を推定する場合は、カメラの内部パラメーター、レンズ歪み、マーカーの実寸が別途必要です。

## 5. 顔検出で試す
教材の顔検出器は、正面に近い顔を検出する学習済みモデル（pico、MITライセンス）です。検出器は教材と同じ場所から読み込み、入力画像は送信しません。
実機のPNGを使い、正しく囲めた顔、見逃した顔、存在しないのに出た枠を数えます。スコアは正しさの保証ではありません。
ロボット専用の対象を追加するには、画像ごとに種類と囲み枠を付け、外部の学習環境で追加学習します。この教材は検出器の追加学習や任意形式のモデル読み込みを行いません。
画像上の枠から実世界の距離や安全な走行方向が直接決まるわけではありません。教材の結果をそのままモーター制御につなげず、まず認識の再現性を検証してください。

記録例：撮影条件 / 実際の対象 / 処理・モデル / しきい値 / 判定 / 見逃し・誤検出 / 次に変える条件。


# 1台のRGB-Dカメラで確かめる

ロボットに搭載するのは、RGB画像とデプス画像を出力するデプスカメラ1台です。通常カメラを追加する構成ではありません。教材の両眼視実験はステレオ方式を想定します。装置内の左右の撮像部とRGB撮影部は、一つの装置に含まれます。ToFなど方式が違う機種では、奥行きの作り方が異なります。

## 1. まず左右の見え方を比べる

ロボットを止め、模様のある箱を0.8 m、1.2 m、2 mなどに置きます。左右の距離計測用画像を出せる機種では、同じ模様の横位置の差を測ります。左右の間隔、校正値、画像の補正方法はドライバーの資料で確認します。RGBの焦点距離を、そのまま左右の赤外線画像の計算に使わないでください。

実際の距離をメジャーで測り、視差が小さくなると同じ1画素の違いが奥行きにどれほど影響するか比較します。測定範囲や数値は機種ごとに異なり、教材の7.5 cm・240 pxは説明用の例です。

## 2. RGB・奥行き・校正値を組にして保存する

ROS 2環境、sensor_msgs、cv_bridge、NumPyを用意します。ドライバー側でRGB画像の歪み補正と、そのRGB座標へのデプスの位置合わせを有効にします。単に同じ大きさにリサイズしても位置合わせにはなりません。

`ros2 topic list -t` と `ros2 topic info <トピック名>` で次を確認します。

- 歪み補正済みのRGB：sensor_msgs/msg/Image
- そのRGBに位置合わせ済みのデプス：sensor_msgs/msg/Image
- そのRGBの校正値：sensor_msgs/msg/CameraInfo（補正後の投影行列P）

以下の名前は仮の例です。実際のドライバーのトピック名に置き換えます。

```sh
python3 robo_lab_rgbd_capture.py --rgb /rgb/image_rect --depth /depth/aligned_to_rgb --info /rgb/camera_info --aligned --output rgbd-images --count 5
```

`--aligned` は位置合わせを行う命令ではなく、ドライバー側で設定済みであることの確認です。スクリプトは共通の光学座標、画像サイズ、校正値、時刻差50 ms以内を確認しますが、実際に同じ物へ位置合わせできていることまでは保証しません。最初はロボットも対象も静止させ、箱の輪郭がRGBとデプスで一致するか確認してください。

32FC1はm、16UC1は既定で1単位=1 mmとして読みます。ドライバーが別の倍率を使うなら `--depth-scale` を変更します。0、NaN、Infなどの無効値はJSONのnullとして保存します。対応はROS REP 118とドライバー仕様を確認してください。デプスは正面方向のZであり、画面の端の物への斜めの直線距離とは異なります。

スクリプトは最大640×480になるよう同じ画素位置を間引き、校正値も合わせて縮小します。画像を購読して保存するだけで、走行指令は出しません。この環境ではROS 2機体を使った動作確認はしていません。

## 3. ブラウザで同じ実験を行う

「画像処理 → 奥行きと動きを調べる → RGBと奥行きを使う」で「RGB-Dログを開く」を押し、保存したJSONを選びます。色・奥行き・3D位置を押して確認し、色だけで対象を選ぶ場合と奥行きも使う場合を比較します。普通の写真やブラウザのカメラ撮影から奥行きを生成する機能ではありません。

同じ赤い箱を手前と奥に置く、模様の乏しい面や反射する包材を撮る、見る角度を変える、といった条件を一つずつ変えます。測れない画素を「近い」「障害物がない」とみなさず、不明の割合も記録します。

顔検出の章でも同じRGB-D JSONを開けます。検出器にはRGBだけを入力し、検出枠の中央半分にある有効な奥行きの中央値を併記します。有効画素が半分未満なら不明です。枠は物体の正確な輪郭ではないため、背景や別の物が混ざっていないか見てください。RGBの写真だけでは奥行きは表示しません。

## 4. SLAM・制御・強化学習へ使う際の違い

- 点群1枚はカメラから見た面です。機体の取付位置・向きのtf変換と、撮影ごとの自己位置がなければ、地図として重ねられません。RGB-D SLAMは別途実装・検証が必要で、教材のLiDAR SLAM推定器に自動的に加わるわけではありません。
- 2D LiDARはある高さの断面を測り、デプスカメラは限られた前方視野の面を測ります。校正後に同じ対象・同じ位置で比較します。デプスのZをそのままLiDARの斜め距離と比較しないでください。
- 距離を制御や学習に使うなら、無効値・遅れ・視野外も扱う必要があります。RGBで目印を識別し、対応するデプスで奥行きを測り、機体座標へ直してから観測を作ります。実機へ移す際は有効画素の割合、通信断、停止手段も検証します。
