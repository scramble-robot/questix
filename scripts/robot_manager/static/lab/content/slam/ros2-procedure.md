# QUESTiX LAB：ROS 2で計測して、SLAMの実験を確かめる

## 目的
同じ走行の計測ログから「車輪だけ」「車輪＋IMU」「車輪＋IMU＋LiDAR」を再計算し、推定位置・地図の違いを調べます。プログラムはセンサーを購読するだけで、モーター指令は送りません。

## 教材から実機へ進む順序
1. **位置と向き**：床に基準点とx・yの方向を決め、機体の前・左と区別します。床の目印までの距離を実測し、機体の向きを変えたときの関係を説明します。
2. **車輪とIMU**：直進とその場回転を別々に記録し、距離と角度を実測します。静止中のジャイロが0に近いか、左右の車輪の符号が正しいかを確かめます。
3. **LiDARの点と地図**：壁までの距離、センサーの取り付け方向・高さを実測します。棚の裏が未観測であることを、別の位置から測って確認します。
4. **位置を決めにくい場所**：同じような壁が続く場所と、角や棚の端が見える場所を比べます。同じコースを、同じ測定データで再計算します。
5. **一周した結果**：出発点だけでなく途中の測定点、壁が二重になる場所も比べます。戻った位置だけが合っていても、途中が正確とは限りません。
6. **実用SLAMで追加確認**：ループ閉じ込みや占有地図を持つROS 2のSLAM実装で、一周前後の地図と軌跡を比較します。以下の収録スクリプトとHTMLの総合実験は局所SLAMの比較であり、ループ閉じ込みや実機の占有地図生成は行いません。

ブラウザの導入にある占有地図は、位置を既知とする地図づくりの実験です。ループ閉じ込みも、手で確認した対応と既知の向きから位置だけを調整する別の小実験です。総合実験のエンジンと混同しないようにします。

### ROS 2での座標の名前
- **base_link**：機体に固定した基準。取り付けたセンサーの位置と向きを、この基準へ変換します。
- **odom**：移動を積み重ねる連続した基準。短い時間の動きには便利ですが、ずれが蓄積します。
- **map**：地図を基準にした位置。周囲との照合で推定を修正すると、位置の値が急に変わることがあります。
通常は map → odom → base_link の関係をtfで表します。frame_idを付け替えるだけでは値は変換されません。この教材のJSONは出発位置を0、出発時の正面を+xとする形式で、tfを購読・配信しません。

### センサーの時刻・取り付けをそろえる
「回転した後のLiDAR」と「回転する前の車輪・IMU」を同じ時刻として扱うと、正しい値でも地図が二重になります。まず同じ時計・タイムスタンプを使い、欠測がないかを確認します。LiDARを機体の中央からずらして取り付けた場合は、その距離と角度を設定します。比較では条件を一つずつ変えます。

## 教員・開発担当者による準備
- ROS 2環境と各センサードライバーを起動します。Pythonのrclpy、sensor_msgsが必要です。
- 左右の回転数をsensor_msgs/JointStateのvelocity（rad/s）、IMUをsensor_msgs/Imu、LiDARをsensor_msgs/LaserScanとして配信します。
- IMUの角速度・加速度は、機体のx前方、y左、z上の座標軸へ変換してから入力します。ジャイロzの正は左旋回です。収録スクリプトはtf変換をしません。frame_idの名前だけ変えても座標変換にはなりません。
- 車輪は前進が正です。実機のジョイント軸に合わせてleft_sign、right_signを指定してください。左右の回転数の符号、半径、左右間隔を実測します。
- LiDARの位置（x前方、y左）と角度（左向き正、rad）を指定します。水平取り付けが前提です。
- 全センサーのheader.stampを同じ時計に合わせます。IMU・車輪は最低10 Hz程度、LiDARは5 Hz以上を目安にします。時刻0や欠測を放置しないでください。
- 低速で走らせる区画を確保し、操縦担当者と非常停止担当者を決めます。ロボットの物理的な停止手段を用意します。

## 収録例
ROS 2の環境設定とロボットの起動を済ませたターミナルで実行します。値とトピック名は実機に合わせて置き換えてください。

```bash
python3 robo_lab_record.py --ros-args \
  -p joint_topic:=/joint_states -p imu_topic:=/imu/data -p scan_topic:=/scan \
  -p left_joint:=left_wheel_joint -p right_joint:=right_wheel_joint \
  -p left_sign:=1.0 -p right_sign:=1.0 \
  -p radius:=0.065 -p track:=0.32 -p imu_frame:=base_link \
  -p lidar_x:=0.0 -p lidar_y:=0.0 -p lidar_yaw:=0.0 \
  -p output:=experiment-01.json
```

1. 収録開始後2秒以上、完全に静止します。
2. 床に測った長方形のコースを低速で一周します。角や途中の測定点でも止まり、時刻と実際の位置を記録します。
3. 最後は出発時の位置と向きに機体を正確に合わせます。これができていないと、戻り位置の誤差は判断できません。
4. Ctrl+Cで記録を保存します。同名ファイルは上書きしません。記録が3フレーム未満の場合はトピック名・時刻・ジョイント名・IMUの座標系を確認してください。
5. 教材の「ROS 2の実機で確かめる」からJSONを開きます。
6. 同じログで3つの方法を比較します。IMUの補正有無も変えてみます。

収録は最大1,000フレーム、5 Hz程度、1走査180点以下です。センサーの時刻を用いて車輪とジャイロを区間平均します。欠測が長いときは、誤った移動量を作らないよう収録処理を停止します。Ctrl+Cで保存し、新しいファイルへ収録し直してください。LiDARの走査中の移動補正はしないため、急旋回を避けてください。

出発点は(0,0)、出発時の正面を+x、その左を+yとします。実機ログには正解位置がないため、ブラウザは誤差を勝手に表示しません。床の測定点と推定軌跡を比較してください。往復で誤差が相殺される場合があるので、戻り位置だけでは精度は分かりません。

## データ形式
ファイル全体がJSONです。サンプルJSONはシミュレーションの記録です。読み込み時は正解位置を除外し、実機ログと同様にセンサーのみで再計算します。

```json
{
  "format": "robo-lab-sensors-v1",
  "stationarySeconds": 2,
  "config": {
    "radius": 0.065, "track": 0.32, "rangeMax": 3.2,
    "lidar": {"x": 0, "y": 0, "yaw": 0}
  },
  "frames": []
}
```

framesの各要素：t=開始からの経過秒（正・昇順）、leftRpm/rightRpm=直前フレームからの平均rpm、gyroZ=同区間の平均rad/s、angleMin/angleIncrement=LiDAR座標でのrad、ranges=各方向のm（測定不可はnull）。angleIncrementは正、角度0が前、反時計回りが正です。最初のフレームも時刻0からの平均値です。開始時に必ず静止してください。

3〜3,000フレーム、距離は合計25万点以内、1走査12〜720点、ファイル12MB以下。optionalのaccel/gyro/magは3要素配列（m/s²・rad/s・µT）です。磁気とカメラ画像は、この簡易収録スクリプトでは収録しません。現在の位置推定にも使いません。

## 教材と実用的なSLAMの違い
総合実験と実機ログの推定は局所的なICP照合と点群地図です。ここには大域的なループ閉じ込み、占有地図、経路計画、画像SLAM、3Dの傾斜補正は含みません。導入の占有地図と全体調整は、その原理を別々に体験する小実験です。実機で地図全体の整合や自律走行を試す段階では、ROS 2のSLAM実装とナビゲーション系で別途検証してください。今回提供するスクリプトは実機未検証です。
