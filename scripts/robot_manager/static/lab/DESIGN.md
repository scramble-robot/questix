# QUESTiX LAB・web joy コントローラー・Robot Manager の許可表示の設計原則

0.6.3 草案（2026-10-23）。実装と受け入れの記録は本書から分ける。

- S：安全の状態と停止を見失わせず、無効の間に押し始めた操作を再開させない。
- H：使えない操作も残し、理由と次にすることをそばに示す。
- L：状態が変わっても、走り始めても操作部を動かさず、停止ボタンの場所を先に確保する。
- N：学ぶ単位と長い作業はページ、補足は折りたたみ、短い中断はポップアップに分ける。
- V：原値・時刻・欠測を保ち、丸め・制限・軸で意味を変えない。
- G：時間グラフを共通部品へそろえ、凡例と文字を描画領域の外に置く。
- C：色を役割で使い、形・文言・コントラストでも意味を伝える。
- U：文字の拡大、操作の大きさ、3 つの画面幅、選択中の表示、動きの抑制で、誰でも読めて操作できるようにする。

優先順位は次のとおり。衝突したら上位を守り、例外は本書に記録する。

1. リポジトリルートの `AGENTS.md` の LAB・bridge・許可・非常停止の安全契約と `questix_msgs/README.md`。
2. 本書 `scripts/robot_manager/static/lab/DESIGN.md`。
3. 参考資料：外部の計測グラフの設計原則、配色の方針、教材の画面のガイド。本書はそれらの内容を QUESTiX LAB に合わせて書き直したもので、参考資料の名前や版には依存しない。

## 1. 目的と範囲

- 対象は生徒が使う QUESTiX LAB 全画面。LAB の実機ダイアログ内の保守表示も含む。
- `web_joy_driver/static/index.html`（ルート相対）のブラウザのコントローラーページも対象とする。ロボットを直接動かす画面である。
- 本書の配置は `scripts/robot_manager/static/lab/DESIGN.md` のままとする。
- Robot Manager は、操作タブの許可と非常停止の表示だけを対象とする。ほかのタブと、操作タブの起動・設定などの画面は対象外。点検で関連する原則を参考にするときは「参考」と明記する。
- 既存のヘッダー・ロゴ・配色の構造を保ち、共有部品から点検する。
- 2026-10-21 の授業版には取り込まない。本書は設計基準で、実装や実機の合格記録ではない。
- 冒頭の優先順位で安全契約を最優先にする。
- FACT はソースで確認した事実、HYP は未検証の見込み、VALUE は採る基準と判断を表す。
- 各規則の「理由（#218）」の A-1〜E は Issue #218 の項目の番号で、本書の規則の番号ではない（たとえば #218 の C-1 はグラフの不具合で、本書の C-1 は色の規則）。

web joy での読み替え（0.5.0）：

- S-2：LAB のヘッダーの停止ボタンは web joy のヘッダーの「止める」（`#stop`）に当たる。Esc はこの端末の入力を離すだけで、全体の停止キーとは案内しない。
- S-3：止めるボタンの ■ は、文字でも CSS の図形でもよい。
- S-7：drive フレームだけでなく、スティック・FIRE・ROLLER・TILT・キーボードのすべての入力に当てはめる。許可（`/motion_permission`）を受け取っていない間は、ページは許可で押下を止めず、ノード側の判断に任せる（S-6）。
- U-4：両手で操作するためのピンチズームの禁止は、L-1 を守るための例外とする。利用者がブラウザの標準 UI で行えるページの拡大 200 % で、操作・状態・文字が読めることを確かめる。基本幅 1280・820・1180 px に対し、拡大後の CSS 幅 640・約 410・約 590 px で確認する。文字だけを 2 倍にする合成試験は使わない。自動ブラウザでの確認と、iPad の Safari の「ページの拡大」での実端末の確認は別に記録する。
- U-6：1280 px（PC）・820 px と 1180 px（iPad の縦と横）を基本とする。PC と教育用タブレットを対象とし、スマートフォンは対象外とする。標準 UI の 200 %（CSS 640・約 590・約 410 px）も確認する。
- 未決（web joy）：帯に複数の状態が重なったときの優先順位、中立待ちの案内をいつまで出すか、分かっている停止理由（stop・timeout・owner_change）を出すか。#220 の点検（2026-10-18）で見つかった。

### Robot Manager の操作タブの許可と非常停止の表示への当てはめ

| 原則            | 当てはまるか | 理由・読み替え                                                                                                                                                                                     |
| --------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S（安全の状態） | 一部         | S-1・S-4・S-6 を適用。先生が許可を要求する画面と、ROS 側で動作を許す判断を区別する。S-2・S-3 は LAB／web joy の停止操作、S-5・S-7・S-8 は LAB の確認・動作入力の規則で、許可の選択へは読み替えない |
| H（隠さない）   | 当てはまる   | 許可を選べないモード・停止中・確認中でも選択肢を残し、理由を示す。H-2 でも中立の注意と非常停止の状態は折りたたまない                                                                               |
| L（ずらさない） | 一部         | L-1・L-2 を適用。選択や理由の変化で操作部を動かさない。L-3 の LAB の停止ボタン配置と L-4 の教材間の報告配置は適用しない                                                                            |
| N（開き方）     | 対象外       | 教材のページ・補足・実機ダイアログの開き分けを、この許可カードへ持ち込まない                                                                                                                       |
| V（値）         | 一部         | V-1・V-4 を適用。要求した選択と Manager が保持する許可と ROS の受信状態を混同しない。V-2・V-3・V-5〜V-9 の数値・系列の規則は対象外                                                                 |
| G（グラフ）     | 対象外       | 許可と非常停止の表示に時間グラフを加える規則ではない                                                                                                                                               |
| C（色）         | 一部         | C-1・C-2・C-4 を適用。選択と非常停止を色だけに頼らず示す。C-3 の LAB の palette／tokens とダークモードの時期は Manager には適用しない                                                              |
| U（使いやすさ） | 一部         | U-2〜U-10 を適用。U-1 の単元と実験の階層は適用しない。U-3 は許可の排他的な選択として読む                                                                                                           |

段階 5（#212）の画面は、操作タブの 1 枚のカードに、走行と発射を別々の 3 択で置く。次の表は Manager が保持する同じ種類の許可の対応であり、ロボットが動けるという表示ではない（S-1・S-6）。

| 選択                 | `/actuation_authority` | `/lab_permission` |
| -------------------- | ---------------------- | ----------------- |
| 許可しない           | OFF                    | OFF               |
| コントローラーのみ   | ON                     | OFF               |
| コントローラーと教材 | ON                     | ON                |

走行は `drive_allowed`、発射は `launcher_allowed` にそれぞれ対応する。OFF／ON は信号の値の意味で、送信頻度・QoS・リース・停止時の送信の契約は変えない。`/motion_permission` は票を受け取る側の判断であり、この表や画面で生成しない。

- 配信停止では「コントローラーと教材」から「コントローラーのみ」へ下がる。元から「許可しない」「コントローラーのみ」なら上げない。
- モードの切替・「すべて止める」では両方とも「許可しない」へ戻る。Manager の起動・終了、ロボット制御の起動／再起動／停止、heartbeat の失敗でも既存の許可解除を維持する。再接続や古い応答で許可を戻さない。
- 保存したモードと実行中のモードがともに教材のときだけ選べる。練習・大会、停止中、実行中のモードが不明・不一致のときは、3 択を無効で残し、理由を示す（H-1・H-3）。練習・大会で選べないことを「ロボットが停止している」と表示しない。
- 「コントローラーから手を離してください」は、未選択・無効・送信中を含め、カードを表示している間は常に見せる（S-6）。
- 「許可しない」は許可の解除であり、物理の非常停止や「すべて止める」と同じ機能として表示しない。操作タブの非常停止は受信した状態を表示するだけで、画面から解除しない（S-6・C-4）。ヘッダーの状態表示を参照しても、ヘッダーのほかの操作は範囲に加えない。
- 許可の選択肢には「止める」「停止」の語、停止の赤、■ を使わない（S-3・C-4）。
- 3 択の実装は専用の Issue と別の PR で行う。この文書の更新では実装せず、2026-10-21 の授業版へ入れない。

## 2. 安全の状態を伝える（S）

### S-1 状態の場所を固定する

- 決まり（VALUE）：非常停止・許可・接続の状態は、常に表示するヘッダーを正本とし、不明も示す。ヘッダーはスクロールで隠さない。CSS 幅 915 px 以上では高さ 109 px の 1 行とし、ロゴ・非常停止・許可・実機・止める・教材一覧・教材の切り替えを順に置く。非常停止と許可は名前と値の 2 段、実機は名前と接続の段階の 2 段にする。狭い幅や標準 UI の 200 % では高さ 88 px の 2 行とし、2 行目は左から一定の間隔で詰めて並べる。接続は広い幅では実機ボタン、狭い幅では状態の行だけに表示し、重ねて表示しない。状態の表示は削らず、札と実機ボタンは最長の文の場所を先に確保し、初回接続も含め状態が変わっても右の要素を動かさない。長いロボット名は 1 行の省略表示とし、全文を title と読み上げ名に残す。
- 各操作部の帯は、その操作に固有の理由を同じ位置に表示する。ヘッダーと同じ状態を出す場合は一致させる。
- Robot Manager の操作タブの非常停止の行（1 章）はこれまでどおりとする。
- Robot Manager では、先生の許可の選択、ROS 側の動作許可、非常停止の状態を別々に示す。許可を ON にしたことだけで「動かせます」「非常停止解除」と断定しない。
- 理由（#218）：A-1・A-3。停止理由が変わっても、見て確かめる場所を探し直させない。
- 確かめ方：非常停止・許可・接続・操作主体を順に変え、ヘッダー・状態帯と操作部の座標を比較する。スクロール・狭い幅・標準 UI での拡大でも、ヘッダーの状態が欠けず、本文に重ならないことを確認する。
- 確かめ方（段階 5）：走行・発射を独立に 3 択で切り替え、選択と確定した許可を照合する。非常停止は押下・解除・未受信・途絶を別々に与え、許可の選択でその表示が書き換わらないことを確認する。

### S-2 画面から停止へ届く

- 決まり（VALUE）：実機との接続後は、常に見えるヘッダーに「■ 止める」を 1 つ置く。モーダルを開いている間は、各ダイアログの固定見出しに同じ働きのボタンを 1 つ置く。押すと、状態や操作主体によらず任意のページの LAB 走行とローラーを両方止める。Esc は、このページ自身の走行とローラーを止める。ほかのページのものは止めない。全体の停止キーとは案内しない。
- 理由（#218）：A-2・D-2。別ページの走行やローラーまで Esc で止めると、資料を閉じる操作と混同する。
- 確かめ方：通常画面・開いたダイアログ・タッチ操作で停止を確認。他ページとの停止範囲も区別する。
- 停止ボタンは仰角を変えず、始まった 1 発の発射は取り消せない。コントローラーと他の経路の指令、物理の非常停止とは別であることを読み上げ名と title でも示す。Esc は全体停止キーとは案内しない。
- キーの伝播を止める dialog の中でも、Esc はこのページ自身の走行とローラーを止める。止める処理は dialog を閉じる処理より先に、document の capture 段階などで受ける。閉じるだけで走行を続けさせない。
- FACT（364a88b、2026-10-18 のブラウザ確認）：補足の dialog（`js/shell/supplement-ui.js`）を開いて Esc を押すと、dialog は閉じるが走行は続いた。ページの上と実機ダイアログでは止まった。

### S-3 停止ボタンの意味を保つ

- 決まり（VALUE）：停止ボタン（LAB の `.drive-stop`・`.lab-stop`・発射の停止、web joy の `#stop`）は赤を保ち、「止める」の文言と ■ を併用する。■ は文字でも CSS の図形でもよい。
- FACT（364a88b）：LAB の停止ボタンは「止める」だけで ■ がない。web joy は CSS の ■ がある。
- 理由（#218）：A-2。停止を色だけに頼らず見つけられるようにする。
- 確かめ方：グレースケール、キーボード、基本幅と 200 % で、停止の文言・記号・操作領域を確認する。

### S-4 動かす操作を装飾で促さない

- 決まり（VALUE）：実機を動かすボタンに光る縁・点滅・拡大縮小による誘導を付けない。
- 理由（#218）：A-1・A-3。動かせることを、動かすべきことに見せない。
- 確かめ方：開始・走行・拒否の各状態で演出を確認。動きを減らす設定でも意味が残ることを確かめる。

### S-5 確認を解除した理由を出す

- 決まり（VALUE）：安全確認を外したら、次の走行のために確認し直す旨をそばに表示する。
- 理由（#218）：A-4。チェックが勝手に消えたと誤解させない。
- 確かめ方：完了・途中停止・記録失敗・開始拒否を分け、解除の有無と文言が一致することを確認する。

### S-6 安全の権威を画面へ移さない

- 決まり（VALUE）：画面は受信状態と拒否理由を伝える。安全許可・非常停止の最終判断を代行しない。
- 理由（#218）：A-3・B-3。見た目の改善のために安全ゲートや中立待ちを緩めない。
- 先生の操作許可と教材の許可は Robot Manager がその場限りの状態として保持し、`/actuation_authority`・`/lab_permission` で伝える。LAB と web joy のページはこれを変更しない。Manager の許可画面だけが既存の許可 API に先生の選択を要求し、Manager が確定した値を表示する。ROS の非常停止・動作許可の判断は代行しない。
- web joy のページも、止める判断は ROS 側の非常停止・`/motion_permission`・各ノードにあり、ページの表示や latch はそれを代わりにしない。
- 保持する契約：bridge の `needs_neutral`、#208 の再開条件、arbiter の入力選択、drive の停止判定。非常停止・走行許可・教材許可を分け、未受信や途絶を解除・許可へ倒さない。
- 段階 5 では 1 章の許可の対応と解除を保ち、「コントローラーから手を離してください」を常時表示する。「許可しない → コントローラーのみ」と「許可しない → コントローラーと教材」のどちらを直接選んでも、走行の許可が上がるため既存の中立待ちが必要で、「コントローラーのみ → コントローラーと教材」という選択だけでは新たな中立待ちを発生させない。他の停止理由がある場合は、その条件を保つ。画面から中立の信号を作って待ちを解かない。
- 確かめ方：drive フレームは `js/live/drive-link.js`、発射フレームは `js/live/shoot-link.js` に限定されることを差分で確認する。
- 確かめ方（段階 5）：偽の API で 3 択・配信停止・モードの切替・「すべて止める」・再接続・heartbeat の失敗を与え、1 章の対応と注意の常時表示を確認する。ROS の信号と中立待ちは別に実機で照合し、API の試験で合格にしない。

### S-7 無効な押し始めを持ち越さない

- 決まり（VALUE）：許可 OFF・非常停止・通信待ちなど、押し始めが無効なら、押したまま有効になっても drive フレームを送らない。離して押し直したときだけ始める。
- 理由（#218）：A-3。H-1 の「使えない操作も見せる」と組にし、無効な押下を有効な操作へ持ち越さない。
- 画面側でも守り、#208 の `DrivePressLatch` と bridge の `needs_neutral` だけに依存しない。
- 対象は drive フレームと発射のフレーム（ローラー・チルト・発射）。画面が守るのは、画面が受け取っている状態（非常停止・教材の許可・通信・操作役）による押し始めまで。受け取っていない許可はノードと bridge の判断に任せ、画面が推測で許可や不許可を作らない（S-6）。
- 確かめ方：押したまま許可 OFF→ON・非常停止解除を行い、押し直すまで drive フレームが 0 件であることを確認する。中立の drive フレームも送らない。
- 実機：H-1 の実装後に ID13 で #208 の NOT_RUN 項目「LAB のボタンを押したまま許可 OFF→ON」を確かめる。

### S-8 押下が終わる合図を取りこぼさない

- 決まり（VALUE）：押している間だけ動く操作は、`pointerup`・`pointercancel`・`lostpointercapture`・ページ非表示の `visibilitychange`・`pagehide` で止める。
- 理由（#218）：A-1・A-3。押下の終了や入力の取り消しで動作を継続させない。
- 確かめ方：各合図を発生させ、継続する drive フレームが止まり、停止の送信を終えた後に新しい非ゼロ指令が出ないことを確認する。
- 確かめ方：タッチ端末でスクロールを始め、押下が取り消され停止することを確認する。
- 未決：ウィンドウの `blur` でも止めるか。スクリーンショットなどの操作でも止まるため、扱いを決める。

## 3. 操作を隠さない（H）

### H-1 使えない操作も見せる

- 決まり（VALUE）：使えない操作は無効状態で残し、理由と必要な次の行動を近くに置く。
- 無効の間は押下を受け付けない（`disabled`、押下を記録しない）。操作部を見せるために S-7 の守りを緩めない。表示の変更と送信の条件の変更を同じ差分に混ぜない。
- 残した無効の操作の名前は読める濃さにする（C-2）。無効であることは理由の文言でも示す。
- 理由（#218）：A-3。許可が戻ったときに操作部が突然現れるのを防ぐ。
- 確かめ方：許可 OFF・通信断・非常停止で操作が残ること、押しても drive フレームが送られないことを確認する。

### H-2 長い説明の入口を残す

- 決まり（VALUE）：長い理由・参考説明は折りたためるが、見出しと今の停止理由は常に見せる。
- 理由（#218）：A-1・D-2。説明の量で主要操作が埋もれないようにする。
- 確かめ方：閉じた状態でも停止理由が分かり、開いても押下中の操作部が動かないことを確認する。

### H-3 有効表示と実際の操作をそろえる

- 決まり（VALUE）：実行できない操作を有効に見せない。無効な理由は色以外でも伝える。
- 許可の変更は、送信中の要求と確定した選択を区別する。失敗や確認不能を成功表示にせず、古い応答で新しい選択や許可解除を上書きしない。素早く選び直しても、成功時は追加の操作なしで最後の要求と確定表示が一致する。失敗時は確定できた状態と失敗理由を示し、許可を自動で上げ直さない。
- 理由（#218）：A-3・B-3。有効に見えて反応がない状態を避ける。
- 確かめ方：各 blocker を注入し、disabled・理由・送信の有無を同じ試験で照合する。
- 確かめ方（段階 5）：応答の遅延・順序の逆転・失敗と、送信中の配信停止・モード変更を与え、最後の要求・Manager の保持値・確定表示を照合する。API で確かめたことと ROS の最後の値の実機確認を分ける。

### H-4 理由で部品の形を変えない

- 決まり（VALUE）：非常停止・許可 OFF・通信待ちでも、同じ操作は同じ形と順序で表示する。
- 理由（#218）：A-3。無効表示と非表示を理由ごとに使い分けない。
- 確かめ方：同じ画面の状態別 DOM と表示を並べ、操作のラベル・順序・占有領域を比較する。

## 4. 操作部をずらさない（L）

### L-1 状態変更で座標を変えない

- 決まり（VALUE）：幅と向きが同じなら、非常停止・許可・通信・blocker の変化で操作部を動かさない。
- 理由（#218）：A-1。押している間にボタンがカーソルや指から外れるのを防ぐ。
- 確かめ方：状態変更の前後・更新中のボタンの矩形を測り、x・y・幅・高さに差がないことを確認する。

### L-2 可変の説明を操作部から離す

- 決まり（VALUE）：変わる文言は操作部の下、または十分な領域を確保した枠へ置く。文字を切らない。
- 教材が差し込む要素（設定・説明・入力欄）は、共有の走行・発射の操作部と状態の帯より上で出入りさせない。状態で変わる設定は、無効にして同じ場所に残す（H-1）。
- 理由（#218）：A-1。理由が短い一文へ変わるだけでも高さが変わる。
- 確かめ方：理由が 0 件・複数件・長文のときと文字 200% で、操作部と説明の重なりを確認する。

### L-3 停止ボタンの場所を先に確保する

- 決まり（VALUE）：停止ボタンの場所は初回接続の前からヘッダーに確保し、つながるまでは非表示、接続後の切断では無効にして残す。走行・ローラーの開始と停止でヘッダーの並びを変えない。「実機」ボタンの意味は変えない。
- 下の停止バーとその予約余白は使わず、ヘッダーの高さと状態の場所は S-1 に従う。ダイアログでも、停止ボタンと状態をスクロールで隠さず、目次と重ねない。教材内の対になる停止ボタンも残す。
- FACT（364a88b、ブラウザ確認）：動作確認のボタンを押すと、押している間にそのボタンが 33 px 上へ動いた（余白 96 px の追加による）。発射は 96 px、同時なら 176 px を足す。
- 理由（#218）：A-2。走行開始と同時の余白追加で画面を動かさない。
- 確かめ方：接続後の停止・走行・ローラー回転・終了・切断でヘッダーと停止ボタンの座標が変わらず、ダイアログ内でもボタンへ届くことを確認する。

### L-4 共通の実験を同じ配置にする

- 決まり（VALUE）：操作・状態・報告の並びを教材間で共通にし、グラフの可読幅を先に確保する。
- 時間グラフを含む走行の報告は、表と横に並べない。報告は本文の幅いっぱいに置き、表はその下に置く。
- 理由（#218）：D-1。同じ走行報告を、表の隣の半幅へ無理に押し込まない。
- 確かめ方：同じ走行の報告を motor と control で表示し、3 幅で軸・凡例・操作を比較する。
- 例外：利用者による折りたたみ開閉や幅・向きの変更は通常の再配置を許す。ただし押下中の操作部は動かさない。

## 5. 開き方を使い分ける（N）

### N-1 学ぶ単位と長い作業はページにする

- 決まり（VALUE）：単元・実験・長い作業はページで開き、ブラウザの「戻る」で戻れるようにする。「測定データを分析する」は教材のトピック（ページ）にする。
- 理由（#218）：D-2。元の作業を覆ったまま長時間操作させない。
- 確かめ方：教材から分析へ進み、戻る・再表示で入力と結果の扱いが明確であることを確認する。

### N-2 今の作業の補足はその場で開く

- 決まり（VALUE）：実験の凡例・短いヒント・結果の詳細は、作業の近くで折りたたむ。
- 理由（#218）：D-2。図と説明を同時に見られるようにする。
- 確かめ方：補足を開いて図と操作が見えること、主たる作業が別ダイアログへ移らないことを確認する。

### N-3 ポップアップは短い中断に限る

- 決まり（VALUE）：接続設定・記録選択・参考資料だけを短く開く。実機の動作操作や長い分析を置かない。「動作確認」は実機の接続画面と並ぶページの区画へ移す。
- 理由（#218）：D-2。操作対象を隠さず、Esc の役割を分かりやすくする。
- 確かめ方：全 dialog 内の操作を一覧にし、ロボットを動かす入口がないことを確認する。

### N-4 閉じ方とフォーカスをそろえる

- 決まり（VALUE）：Esc・閉じるボタン・戻り先を用意する。閉じる操作で停止経路を失わない。
- 理由（#218）：D-2。資料を閉じる意味と走行を止める意味の重なりを整理する。
- 確かめ方：キーボードだけで開閉・復帰する。キー伝播を止める dialog 内でも自身の走行の停止を確認する。

## 6. 値を正しく伝える（V）

### V-1 原値と表示を分ける

- 決まり（VALUE）：測定値・送信値・符号・時刻・有効性を表示都合で上書きしない。
- 理由（#218）：B-1・B-2。表示範囲を変えても測定や送信の意味は変えない。
- 確かめ方：軸・テーマ・表示切替の前後で入力データが同じであり、通信や走行を再開しないことを確認する。

### V-2 選択値を見分けられる桁数にする

- 決まり（VALUE）：選択可能な別の値が同じ表示にならない桁数と単位を使う。
- 理由（#218）：B-1。0.05・0.10・0.15 m/s の違いを表示で失わせない。
- 確かめ方：選択肢の値とラベルを列挙し、ラベルの一意性と送信値との一致を試験する。

### V-3 制限後の値を隠さない

- 決まり（VALUE）：要求値を上限で下げるなら、要求値・制限後の値・制限理由を表示する。
- 理由（#218）：B-2。「0.2 m/s」と説明して別の値を送る状態を避ける。
- 確かめ方：上限未満・一致・超過と正負の指令で、説明・選択肢・送信フレームを照合する。

### V-4 分かった理由だけを伝える

- 決まり（VALUE）：拒否・終了は実際の判定理由と一致させる。原因不明は不明と伝える。
- 理由（#218）：B-3。小さい指令と通信途絶を、同じ原因と断定しない。
- 確かめ方：`js/control/live-drive.js` の `wallApproach()` に小さいゲイン・新鮮／途絶した状態を与え、実機は別に照合する。

### V-5 欠測と無効を線で埋めない

- 決まり（VALUE）：無効・欠測・別セッションの境界で線を切る。前値の反復やゼロで測定を補わない。
- 理由（#218）：C-1（#178）。古いフィードバックを新しい実測として見せない。
- 車輪ごとの `feedback_stamp` と `feedback_valid` を使い、新しい有効なフィードバックの点だけを描く。同じ時刻の反復は新しい点にしない。
- 左右の新しさと有効性を別々に扱い、片輪の欠測で健全なもう片輪を消さない。この選別は生の値とフィードバック由来の加工値に適用し、別に更新される指令の系列まで間引かない。再接続・セッション変更・時刻の巻き戻りでは線を切り、新旧の判定をやり直す。
- 次の有効点とのフィードバック時刻の差が 0.15 s を超えたら線を切る。有効性と時刻で新旧を判断し、固定の経過秒数だけで新鮮とは判定しない。
- HYP：0.15 s は停止中の約 0.3 s の再送間隔を連続測定と区別する仮の境界。実際のグラフで確かめて調整する。
- `feedback_stamp` を持たない記録（古い bridge、rosbag の変換）は、時刻の間隔で線を切り、その基準を近くに書く。
- 例外：判断に使った保持値そのものを教える系列（systems の診断など）は、保持値であることを名前と線種で示せば前値を描いてよい。
- 確かめ方：欠測・同一時刻の反復・無効・再接続、0.15 s ちょうど／超過、約 0.3 s 間隔を与え、正常な 0 と空白、古い値が区別できることを確認する。
- 確かめ方：左右を独立に更新・無効にし、フィードバックが反復する間にも指令を変える。健全な片輪と指令が残り、反復した実測を増やさず、時刻の巻き戻りをまたいで線がつながらないことを確認する。

### V-6 加工系列の名前と条件を示す

- 決まり（VALUE）：生の値と加工値を分け、平滑化・間引きの条件を凡例か近くの説明に書く。
- 車輪の保守表示と「実機の状態」は、左右それぞれに同じ系列名（生の値・なめらか・送った指令）を使う。生の値と加工値はどちらも測定由来であり、G-3 の `measured` を使い、太さと系列名でも区別する。加工条件を受け取れない場合は不明と書き、固定の係数を推測して示さない。
- 理由（#218）：C-1。なめらかな線を新しい実測と誤認させない。
- 確かめ方：元記録・加工条件・描画点を照合する。固定のフィルタ説明は実効設定との一致を確かめる。
- 確かめ方：同じ車輪の入力を 2 つの表示へ渡し、系列名・役割・線の区別を比較する。加工条件が既知／不明の両方で、説明が実際に分かる範囲と一致することを確認する。

### V-7 軸の最小範囲を目的から決める

- 決まり（VALUE）：符号付き量は正負を読める軸とし、教材の上限の約 1/3 を最小の幅の目安にする。前後の速さ ±0.05 m/s、回転の速さ ±0.15 rad/s、車輪の回転数 ±10 rpm を採る。
- 理由（#218）：B-4。ゼロを含むだけでは 0.01 rad/s の揺れの過大表示を防げない。
- 1 回の報告の中では軸範囲を縮めない。データが超えたら範囲を広げ、値を切り捨てたり書き換えたりしない。
- HYP：上記の最小範囲は実際のグラフで見て調整する仮の値。LAB の値は前進・後退で正負を取るため、0 から始める軸にはしない。
- `js/core/chart-scale.js` の `niceScale()`・`formatTick()` を再利用する。安全上限を表示上限と混同しない。
- 確かめ方：ゼロ・微小ノイズ・正負の最大値・比較走行で、同じ意味の傾きが同じ尺度で読めることを確認する。

### V-8 時刻の基準を明記する

- 決まり（VALUE）：取得・受信・描画の時刻を区別する。走行中の小さいグラフは受信時刻を維持して「受信した時刻」と画面に書き、報告はロボット側のメッセージ `stamp` を基準にする。
- 理由（#218）：C-1。受信の揺れやフィードバックの反復を、測定の時間変化と誤認させない。
- 確かめ方：異なる受信遅延で同じ記録を再生し、受信時刻の表示と、報告のメッセージ時刻が方針どおりであることを確認する。

### V-9 単位の書き方をそろえる

- 決まり（VALUE）：同じ量は全教材で同じ単位の書き方にする（例：m/s と m/秒 を混ぜない）。どちらに統一するかは `CONTRIBUTING.md` と合わせて決める。
- 理由：同じ値が画面によって別の書き方になると、別の量に見える。
- 確かめ方：content と JS の単位の文字列を一覧にし、量ごとに 1 つであることを確かめる。

## 7. グラフの部品をそろえる（G）

### G-1 時間グラフの共通部品を使う

- 決まり（VALUE）：時間系列は `js/core/html-chart.js` にそろえ、教材は系列・単位・範囲を渡す。
- 理由（#218）：C-1・C-2。凡例や欠測を別々の実装で直す状態を解消する。
- 確かめ方：同じ系列を保守表示・実機状態・走行報告へ渡し、軸・欠測・凡例が一致することを確認する。
- 例外：LiDAR の空間表示や軌跡図は時間グラフではない。無理にこの部品へ置き換えない。

### G-2 凡例と文字を描画領域の外へ置く

- 決まり（VALUE）：凡例は描画領域の外に置く。線の名前は領域外の余白にだけ置いてよく、両方を必須にはしない。描画領域の中に文字を置かない。
- 理由（#218）：C-1・C-2。終点のラベルをずらすだけでは、途中の線との重なりを防げない。
- 確かめ方：同値・交差・右端・最大系列数で領域内に文字がなく、領域外のラベルが重ならず、基本幅と標準 UI の 200 % でも読めることを確認する。
- `js/core/palette.js` 冒頭の直接ラベル方針と `CONTRIBUTING.md` の該当箇所は、実装の PR でこの規則へそろえる。本草案の PR では変更しない。
- `js/core/html-chart.js` が描く線名・閾値・縦線・帯の名前も対象とする。G-1 で教材を共通部品へ移す前に、共通部品をこの規則にそろえる。
- データがないときの案内文（「実験すると…」など）は、線と重ならないので描画領域の中に置いてよい。

### G-3 系列の役割を共通にする

- 決まり（VALUE）：`js/core/palette.js` の役割表を正本にし、色・線種・太さ・名前を組み合わせる。
- 理由（#218）：C-1。同じ色が走行開始と右車輪を表すなど、意味が競合するのを避ける。
- 確かめ方：同じ役割が全教材で一致し、左右はパネル名やラベルで区別され、灰色表示でも追えることを確認する。

| 役割     | 意味                             | 色以外の手掛かり（現行定義と採用基準） |
| -------- | -------------------------------- | -------------------------------------- |
| actual   | 実際の値・シミュレーションの真値 | 太い実線、名称                         |
| measured | 測定・推定・判断に使う値         | 細い実線、点や名称を併用               |
| target   | 目標・境目                       | 破線、名称                             |
| plan     | 計画・予測                       | 一点鎖線、名称                         |
| previous | 前回                             | 点線、比較対象の名前                   |
| event    | 出来事                           | 縦線、出来事の文言                     |
| danger   | 接触・非常停止                   | アイコンと状態の文言                   |

## 8. 色を補助情報として使う（C）

### C-1 役割と色以外の表現を先に決める

- 決まり（VALUE）：色名で操作・系列を説明せず、役割・名前・形で説明する。カラーユニバーサルデザイン（CUD）の考え方を参考にした配色とする。
- 理由（#218）：C-1・E。色だけの区別は端末や見る人によって失われる。
- 確かめ方：グレースケールで開始・停止・許可・系列の意味が残り、同じ役割が同じ表現であることを確認する。

### C-2 コントラストを実背景で測る

- 決まり（VALUE）：文字は 4.5:1、意味を伝える線・枠・アイコンは 3:1 以上を目標にする。
- H-1 で残す無効の操作の名前も対象とする。役割の色は線のための色なので、文字に使うときは文字の目標（4.5:1）で確かめる。
- 理由（#218）：E。線種が違っても、線自体が見えにくい問題は残る。
- 確かめ方：通常・無効・ホバー・フォーカスの実背景と合成後の色を測る。白背景だけで全状態の合格にしない。

### C-3 配色の構造を保つ

- 決まり（VALUE）：`js/core/palette.js` の chart／scene と `css/tokens.css` の役割を保ち、必要な色だけ見直す。
- 理由（#218）：E。別プロジェクトの配色を一括導入しない。scene の暗い面はサイト全体のダークモードではない。
- 確かめ方：JS と CSS の同じ役割の値を照合する。ダークモードは DESIGN.md 1.0 と共有部品の修正後に始め、対応時に全組合せを再点検する。
- 表現は「WCAG 2.2 のコントラストを目標にした」までとし、認証や規格全体への適合を主張しない。

### C-4 操作の色の意味を使い回さない

- 決まり（VALUE）：停止・危険の赤、走らせる操作の橙など、操作に付けた色を、別の意味（一般の理由の一覧、問題の印、系列の色）に使わない。
- 理由（#218）：E。赤が「止める」と「先生に伝える一般の理由」の両方を表すと、危険の印が薄まる。
- 確かめ方：赤と橙を使う箇所を一覧にし、意味が 1 つずつであることを確かめる。
- グラフの `danger` の役割も、接触・非常停止だけに使う。誤差・ずれ・注意を表す役割が要るときは、G-3 の役割表に新しい役割を足してから使う。

### U-11 本文の改行と幅

- 決まり（VALUE）：本文の中の明示的な改行は、原則として句点（。）の直後に置く。表示幅による自然な折り返しは、この限りではない。既存の段落は保ち、句点ごとに新しい行を足さない。
- 本文の段落だけに幅の上限を置いて、枠の中に大きな右の空きを残さない。読む幅を制限する場合は、本文と枠の幅をそろえ、全角の文字の幅を基準にして実測する。`ch` を `em` に替えるだけで解決したとは判断しない。
- 見出し・札・操作ボタンと横に並べて説明の文が細くなる場合は、説明の文を別の行に置く。
- 数式・コード・測定値・表・凡例・利用者が入力した文の改行は、その情報の意味に合わせて扱う。ボタン・札の `keep-all` やゼロ幅スペースは、幅による折り返しの調整として本文と分ける。
- 英単語・識別子・URL は単語の途中で改行しない。それらを次の行へ送ったことで残る空きは、幅による自然な折り返しとして右空きの基準の対象外とする。1 行に収まらない長い語だけを `overflow-wrap: anywhere` で折り返す。
- 理由：2026-10-22 の本文改行監査と、作業責任者による改行・段落維持の決定。本文だけの上限と横並びによる、文の途中の折り返しと大きな右の空きを防ぐ。
- 確かめ方：1280・1180・820 px とページの拡大 200 % で、文の途中の行末から枠の内側の有効領域の右端までの空きを測る。全角 5 文字ぶん以上あれば、本文の上限、横並び、隣の表示を調べる。U-4 と同様に、自動試験の近似と実端末の確認を区別する。
