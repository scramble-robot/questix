# QUESTiX LAB 画面の設計原則

優先順位は次のとおり。衝突したら上位を守り、例外は本書に記録する。

1. リポジトリルートの `AGENTS.md` の LAB・bridge・許可・非常停止の安全契約と `questix_msgs/README.md`。
2. 本書 `scripts/robot_manager/static/lab/DESIGN.md`。
3. 参考資料：VAMeter-Edu のグラフ原則、CUD の配色方針、JRT Lab UI 共通ガイド。

## 1. 目的と範囲

- 版：0.1.0 草案。日付：2026-10-17。
- 対象は生徒が使う QUESTiX LAB 全画面。LAB の実機ダイアログ内の保守表示も含む。
- Robot Manager 本体の画面は対象外。その UI の原則は別途決める。
- 既存のヘッダー・ロゴ・配色の構造を保ち、共有部品から点検する。
- 2026-10-21 の授業版には取り込まない。本書は実装や実機の合格記録ではない。
- FACT はソース確認、HYP は未検証の見込み、VALUE は採る基準と判断を表す。
- 各規則の「現状」は静的確認の範囲。「満たしている」は実画面・実機の合格を意味しない。
- ソース基準は `scramble-robot/questix` の `origin/main`、`7da35bc780eef82bdcae2fb4e7291f3fe2141971`。
- [#218](https://github.com/scramble-robot/questix/issues/218) の観察対象は統合版 `364a88b`。本書の基準とは異なる。
- [#178](https://github.com/scramble-robot/questix/issues/178) の記録も課題の入力とし、過去の実機結果を今回の結果にしない。
- #208 の中立待ち・押し直しは統合版側の契約。基準 main に実装済みとは記さない。
- 以下の短いパスは LAB ディレクトリからの相対位置。ルート相対のパスは明記する。

## 2. 安全の状態を伝える（S）

### S-1 状態の場所を固定する

- 決まり（VALUE）：非常停止・許可・操作主体を、各操作部の同じ位置に表示する。不明も明示する。
- 理由：A-1・A-3。停止理由が変わっても、見て確かめる場所を探し直させない。
- 現状（FACT）：`js/live/robot-state.js` の `liveStateStrip()` が共通の状態帯を提供する。常設性は未達。
- 確かめ方：非常停止・許可・通信・操作主体を順に変え、状態帯と操作部の座標を比較する。

### S-2 画面から停止へ届く

- 決まり（VALUE）：走行中は停止バーを使えるようにする。Esc はこのページ自身の走行を止める。
- 理由：A-2・D-2。別ページの走行まで Esc で止めると、資料を閉じる操作と混同する。
- 現状（FACT）：`js/live/drive-ui.js` の `stopBar()` と `js/live/drive-link.js` に停止経路がある。
- 確かめ方：通常画面・開いたダイアログ・タッチ操作で停止を確認。他ページとの停止範囲も区別する。
- 例外：停止バーは任意の LAB 走行を停止できる。Esc は全体停止キーとは案内しない。

### S-3 停止ボタンの意味を保つ

- 決まり（VALUE）：`.drive-stop`・`.drive-bar-stop` は赤を保ち、「止める」の文言と ■ を併用する。
- 理由：A-2。停止を色だけに頼らず見つけられるようにする。
- 現状（FACT）：赤い背景と白文字は `css/live.css` で満たしている。記号と文言は表示箇所ごとに点検する。
- 確かめ方：グレースケール、キーボード、390 px 幅で、停止の文言・記号・操作領域を確認する。

### S-4 動かす操作を装飾で促さない

- 決まり（VALUE）：実機を動かすボタンに光る縁・点滅・拡大縮小による誘導を付けない。
- 理由：A-1・A-3。動かせることを、動かすべきことに見せない。JRT の実行演出は採らない。
- 現状（FACT）：`css/live.css` の走行開始は静的な塗り。停止バーの点滅は動作中の通知として別扱い。
- 確かめ方：開始・走行・拒否の各状態で演出を確認。動きを減らす設定でも意味が残ることを確かめる。

### S-5 確認を解除した理由を出す

- 決まり（VALUE）：安全確認を外したら、次の走行のために確認し直す旨をそばに表示する。
- 理由：A-4。チェックが勝手に消えたと誤解させない。
- 現状（FACT）：`js/live/live-session.js` の `finishRun()` は記録を伴う開始済み走行の後に確認を解除する。理由表示は未達。
- 確かめ方：完了・途中停止・記録失敗・開始拒否を分け、解除の有無と文言が一致することを確認する。

### S-6 安全の権威を画面へ移さない

- 決まり（VALUE）：画面は受信状態と拒否理由を伝える。安全許可・非常停止の最終判断を代行しない。
- 理由：A-3・B-3。見た目の改善のために安全ゲートや中立待ちを緩めない。
- 現状（FACT）：`AGENTS.md` と `questix_msgs/README.md`（ともにルート相対）が責任分界を定める。
- 確かめ方：drive フレームは `js/live/drive-link.js`、発射フレームは `js/live/shoot-link.js` に限定されることを差分で確認。
- 保持する契約：bridge の `allow_drive`・`needs_neutral`、#208 の再開条件、arbiter の入力選択、drive の停止判定。
- `allow_drive` は旧構成を含む識別子。現行の許可を bridge の設定だけで与える規則として読み替えない。
- 非常停止・走行許可・教材許可を分ける。未受信や途絶を解除・許可へ倒さない。

## 3. 操作を隠さない（H）

### H-1 使えない操作も見せる

- 決まり（VALUE）：使えない操作は無効状態で残し、理由と必要な次の行動を近くに置く。
- 理由：A-3。許可が戻ったときに操作部が突然現れるのを防ぐ。
- 現状（FACT）：`js/live/drive-view.js` の `notAllowedLine()` は操作部を説明へ置換するため未達。
- 確かめ方：許可 OFF・通信断・非常停止で操作が残ること、押しても drive フレームが送られないことを確認する。

### H-2 長い説明の入口を残す

- 決まり（VALUE）：長い理由・参考説明は折りたためるが、見出しと今の停止理由は常に見せる。
- 理由：A-1・D-2。説明の量で主要操作が埋もれないようにする。
- 現状（FACT）：`js/live/drive-view.js` の `teacherDetails()` は折りたたみを使う。主要操作との配置は未達。
- 確かめ方：閉じた状態でも停止理由が分かり、開いても押下中の操作部が動かないことを確認する。

### H-3 有効表示と実際の操作をそろえる

- 決まり（VALUE）：実行できない操作を有効に見せない。無効な理由は色以外でも伝える。
- 理由：A-3・B-3。有効に見えて反応がない状態を避ける。
- 現状（FACT）：`js/live/drive-view.js` の `runControls()` は準備不足時の disabled を満たしている。全画面は要点検。
- 確かめ方：各 blocker を注入し、disabled・理由・送信の有無を同じ試験で照合する。

### H-4 理由で部品の形を変えない

- 決まり（VALUE）：非常停止・許可 OFF・通信待ちでも、同じ操作は同じ形と順序で表示する。
- 理由：A-3。無効表示と非表示を理由ごとに使い分けない。
- 現状（FACT）：`js/live/shoot-view.js` の `offLine()` も操作部を別表示にする。走行と合わせて点検する。
- 確かめ方：同じ画面の状態別 DOM と表示を並べ、操作のラベル・順序・占有領域を比較する。

## 4. 操作部をずらさない（L）

### L-1 状態変更で座標を変えない

- 決まり（VALUE）：幅と向きが同じなら、非常停止・許可・通信・blocker の変化で操作部を動かさない。
- 理由：A-1。押している間にボタンがカーソルや指から外れるのを防ぐ。
- 現状（FACT）：`js/live/drive-view.js` の `driveControls()` はボタンより上に可変の一覧を置くため未達。
- 確かめ方：状態変更の前後・更新中のボタンの矩形を測り、x・y・幅・高さに差がないことを確認する。

### L-2 可変の説明を操作部から離す

- 決まり（VALUE）：変わる文言は操作部の下、または十分な領域を確保した枠へ置く。文字を切らない。
- 理由：A-1。理由が短い一文へ変わるだけでも高さが変わる。
- 現状（FACT）：`js/live/drive-view.js` の `checklist()`、`js/live/shoot-view.js` の `shootBlock()` は要改善。
- 確かめ方：理由が 0 件・複数件・長文のときと文字 200% で、操作部と説明の重なりを確認する。

### L-3 停止バーの場所を先に確保する

- 決まり（VALUE）：停止バーの領域を事前に確保するか、操作部と重ならず座標も変えない配置にする。
- 理由：A-2。走行開始と同時の余白追加で画面を動かさない。
- 現状（FACT）：`css/live.css` は走行時に body と開いた dialog へ下余白 96 px を追加するため未達。
- 確かめ方：開始・終了・ダイアログ開閉で操作部の座標とスクロール位置を記録し、バーへの到達も確かめる。

### L-4 共通の実験を同じ配置にする

- 決まり（VALUE）：操作・状態・報告の並びを教材間で共通にし、グラフの可読幅を先に確保する。
- 理由：D-1。同じ走行報告を、表の隣の半幅へ無理に押し込まない。
- 現状（FACT）：`css/motor.css` の `.motor-bench-layout` は 900 px 以上で等幅 2 列となり未達。
- 確かめ方：同じ走行の報告を motor と control で表示し、3 幅で軸・凡例・操作を比較する。
- 例外：利用者による折りたたみ開閉や幅・向きの変更は通常の再配置を許す。ただし押下中の操作部は動かさない。

## 5. 開き方を使い分ける（N）

### N-1 学ぶ単位と長い作業はページにする

- 決まり（VALUE）：単元・実験・長い作業はページで開き、ブラウザの「戻る」で戻れるようにする。
- 理由：D-2。元の作業を覆ったまま長時間操作させない。
- 現状（FACT）：`js/systems/measurement-view.js` の `measurementPanel()` は長い分析作業をポップアップ化しており未達。
- 確かめ方：教材から分析へ進み、戻る・再表示で入力と結果の扱いが明確であることを確認する。

### N-2 今の作業の補足はその場で開く

- 決まり（VALUE）：実験の凡例・短いヒント・結果の詳細は、作業の近くで折りたたむ。
- 理由：D-2。図と説明を同時に見られるようにする。
- 現状（FACT）：`js/shell/supplement-ui.js` 冒頭に同じ使い分けがある。本書で判断基準を明文化する。
- 確かめ方：補足を開いて図と操作が見えること、主たる作業が別ダイアログへ移らないことを確認する。

### N-3 ポップアップは短い中断に限る

- 決まり（VALUE）：接続設定・記録選択・参考資料だけを短く開く。実機の動作操作や長い分析を置かない。
- 理由：D-2。操作対象を隠さず、Esc の役割を分かりやすくする。
- 現状（FACT）：`js/systems/measurement-view.js` の分析と、`js/live/drive-ui.js` の動作確認は移す対象。
- 確かめ方：全 dialog 内の操作を一覧にし、ロボットを動かす入口がないことを確認する。

### N-4 閉じ方とフォーカスをそろえる

- 決まり（VALUE）：Esc・閉じるボタン・戻り先を用意する。閉じる操作で停止経路を失わない。
- 理由：D-2。資料を閉じる意味と走行を止める意味が重なる現状を整理する。
- 現状（FACT）：`js/shell/supplement-ui.js` は閉じた後のフォーカス復帰を満たしている。Esc と走行の併存は要確認。
- 確かめ方：キーボードだけで開閉・復帰する。キー伝播を止める dialog 内でも自身の走行の停止を確認する。

## 6. 値を正しく伝える（V）

### V-1 原値と表示を分ける

- 決まり（VALUE）：測定値・送信値・符号・時刻・有効性を表示都合で上書きしない。VAMeter の P1 を採る。
- 理由：B-1・B-2。表示範囲を変えても測定や送信の意味は変えない。
- 現状（FACT）：`js/core/html-chart.js` は受け取った点から描画座標を作る。描画用変換と原値を分ける構造は満たしている。
- 確かめ方：軸・テーマ・表示切替の前後で入力データが同じであり、通信や走行を再開しないことを確認する。

### V-2 選択値を見分けられる桁数にする

- 決まり（VALUE）：選択可能な別の値が同じ表示にならない桁数と単位を使う。
- 理由：B-1。0.05・0.10・0.15 m/s の違いを表示で失わせない。
- 現状（FACT）：`js/control/ui.js` は速度の表示に `toFixed(1)` を使い、上記 3 値が同じになるため未達。
- 確かめ方：選択肢の値とラベルを列挙し、ラベルの一意性と送信値との一致を試験する。

### V-3 制限後の値を隠さない

- 決まり（VALUE）：要求値を上限で下げるなら、要求値・制限後の値・制限理由を表示する。
- 理由：B-2。「0.2 m/s」と説明して別の値を送る状態を避ける。
- 現状（FACT）：`js/systems/measurement-lab.js` の要求値は 0.2 を含み、`js/live/drive-link.js` は送信前に制限する。明示は未達。
- 確かめ方：上限未満・一致・超過と正負の指令で、説明・選択肢・送信フレームを照合する。

### V-4 分かった理由だけを伝える

- 決まり（VALUE）：拒否・終了は実際の判定理由と一致させる。原因不明は不明と伝える。
- 理由：B-3。小さい指令と通信途絶を、同じ原因と断定しない。
- 現状（HYP）：#218 の低速での誤った拒否文言は統合版の見込み。基準 main での再現・実機原因は未確認。
- 確かめ方：`js/control/live-drive.js` の `wallApproach()` に小さいゲイン・新鮮／途絶した状態を与え、実機は別に照合する。

### V-5 欠測と無効を線で埋めない

- 決まり（VALUE）：無効・欠測・別セッションの境界で線を切る。前値の反復やゼロで測定を補わない。P3・P4 を採る。
- 理由：C-1（#178）。古いフィードバックを新しい実測として見せない。
- 現状（FACT）：`js/core/html-chart.js` の `runs()` は非有限点で線を切り、この部分は満たしている。
- 現状（FACT）：`js/live/robot-state-core.js` の `historyPoints()` は受信間隔 0.5 s 超で切る。ただし車輪の受信更新判定とは別。
- 現状（FACT）：`js/live/live-ui.js` は最新値を履歴へ追加し続けるため未達。同じ feedback の区別も要点検。
- 確かめ方：欠測・同一 feedback stamp の反復・無効・再接続を与え、正常な 0 と空白が区別できることを確認する。

### V-6 加工系列の名前と条件を示す

- 決まり（VALUE）：生の値と加工値を分け、平滑化・間引きの条件を凡例か近くの説明に書く。P3 の派生系列の扱いを採る。
- 理由：C-1。なめらかな線を新しい実測と誤認させない。
- 現状（FACT）：`js/live/robot-state-view.js` は生・加工・指令を分ける。報告は `js/live/drive-report-core.js` の `thin()` で間引く。
- 確かめ方：元記録・加工条件・描画点を照合する。固定のフィルタ説明は実効設定との一致を確かめる。

### V-7 軸の最小範囲を目的から決める

- 決まり（VALUE）：符号付き量は正負を読める軸とし、微小な揺れを過大に見せない最小範囲を決める。P5 を調整して採る。
- 理由：B-4。ゼロを含むだけでは 0.01 rad/s の揺れの過大表示を防げない。
- 現状（FACT）：`js/live/drive-report-view.js` の `valueAxis()` はゼロを含むが、物理量ごとの最小幅がなく未達。
- 確かめ方：ゼロ・微小ノイズ・正負の最大値・比較走行で、同じ意味の傾きが同じ尺度で読めることを確認する。
- 未決：速度・回転・車輪ごとの最小範囲、拡大段階、縮小を許す時点。VAMeter の 0 起点・9 目盛は採らない。
- `js/core/chart-scale.js` の `niceScale()`・`formatTick()` を再利用する。安全上限を表示上限と混同しない。

### V-8 時刻の基準を明記する

- 決まり（VALUE）：取得・受信・描画の時刻を区別し、横軸が何を基準にするか説明する。P2 は LAB の現状に合わせて調整する。
- 理由：C-1。受信の揺れやフィードバックの反復を、測定の時間変化と誤認させない。
- 現状（FACT）：`js/live/live-ui.js` の `recordWheels()` は `performance.now()` でブラウザ受信時刻を保存する。
- 現状（FACT）：`js/live/robot-state.js` は受信時の同じ単調時計を `ingest()` に渡す。`historyPoints()` は現在からの相対秒を返す。
- 現状（FACT）：`js/live/drive-report-core.js` はメッセージの `stamp` と `js/live/recording-core.js` の `commandZero()` の差で経過秒を作る。
- 確かめ方：異なる受信遅延で同じ記録を再生し、測定時刻の軸と受信時刻の軸の差を記録する。
- 未決：ライブの軸もロボット側の時刻へ統一するか、受信時刻の表示として明示して残すか。今回は変えない。

## 7. グラフの部品をそろえる（G）

### G-1 時間グラフの共通部品を使う

- 決まり（VALUE）：時間系列は `js/core/html-chart.js` にそろえ、教材は系列・単位・範囲を渡す。
- 理由：C-1・C-2。凡例や欠測を別々の実装で直す状態を解消する。
- 現状（FACT）：`js/live/live-ui.js` の canvas と `js/live/drive-report-view.js` の独自 SVG は未統一。
- 確かめ方：同じ系列を保守表示・実機状態・走行報告へ渡し、軸・欠測・凡例が一致することを確認する。
- 例外：LiDAR の空間表示や軌跡図は時間グラフではない。無理にこの部品へ置き換えない。

### G-2 凡例を線の外へ置く

- 決まり（VALUE）：系列名と線種の凡例は描画領域の外へ置く。直接ラベルを残す場合も凡例を代用させない。
- 理由：C-1・C-2。終点のラベルをずらすだけでは、途中の線との重なりを防げない。
- 現状（FACT）：`js/core/html-chart.js` の `lineLabels()` は終点座標へ配置する。領域内にも入り、走行報告も終点ラベルを持ち未達。
- 確かめ方：同値・交差・右端・最大系列数でラベルと線が重ならず、390 px と文字拡大でも読めることを確認する。
